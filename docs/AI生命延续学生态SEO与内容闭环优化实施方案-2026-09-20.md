# AI 生命延续学生态 SEO 与内容闭环优化实施方案

更新日期：2026-09-20

## 1. 范围与边界

本方案只优化以下 AI 生命延续学资产：

- AI 生命延续学日报：`https://news.aibioo.cn/`
- AI 生命延续学商机日报：`/opportunity/`
- AI 生命延续学资讯商机项目：`/project-opportunity/`
- AI 生命延续学时间线：`/timeline/`
- AI 生命延续学雷达：`https://radar.aibioo.cn/`

不修改 AI 日报主站、Aivora 商店、个人主页及其后端。本轮不增加 Cloudflare Cron，不引入新平台，不改变三个日报现有定时路由。

## 2. 当前判断

### 已经做得较好的部分

- 日报、两个商机栏目和雷达均有独立入口。
- 线上 robots、sitemap、canonical 和基础结构化数据已经可用。
- 雷达具备论文、临床试验、GitHub、机构 RSS、Papers.cool 和通用 AI 雷达桥接。
- 后端已有 7 天 URL/标题去重、来源失败隔离、Folo、Papers.cool 和 GitHub 搜索。
- 商机与项目商机已经共用一次抓取，避免重复消耗。

### 当前主要问题

1. 日报网站与雷达仍是两个信息孤岛，日报没有直接复用雷达已经清洗和打标的公开 JSON。
2. 商机日报和项目商机日报的页面 description 长期重复，搜索结果无法体现当日主题。
3. 生成正文通常自带一级标题，Hugo 模板又输出一个一级标题，部分页面出现重复 H1。
4. 日报正文已有图片时，页面 Front Matter 没有记录文章主图，Article/社交分享无法稳定使用当期图片。
5. 日期页仍渲染完整历史树，单页 HTML 和站内链接数量过大，上下文内链的重要性被稀释。
6. 页面很多，但面向长期搜索需求的专题中心、方法页和主题归档仍不足。
7. 普通日报与商机栏目之间虽然互相有入口，但缺少统一的“信号 -> 证据 -> 行动 -> 项目”信息链。

## 3. 目标架构

```text
AI 生命延续学雷达
  -> 每小时发现、去重、标注来源和证据阶段
  -> 输出 bio-radar-v1 公开 JSON

CloudFlare-BioAI-Daily
  -> 把雷达简报作为一个可失败、有限量的信息源
  -> 与现有 RSS / Folo / Papers.cool / GitHub 合并去重
  -> 普通日报解释证据和应用距离
  -> 商机日报给出低风险验证动作
  -> 资讯商机项目沉淀可试跑项目和复用资产

BioAI-Daily-Web
  -> 日期页承载完整内容
  -> 栏目页展示最新摘要和精选归档
  -> 专题中心承接长期搜索意图
  -> 雷达、日报、商机、项目、时间线形成清晰互链
```

雷达保持独立更新。日报读取雷达失败时只跳过该来源，不能阻断普通日报或两个商机栏目。

## 4. 分阶段实施

### 阶段 A：页面唯一性与技术基础

状态：已完成本地实现、构建和浏览器预览验收，待远端部署门禁解除

- 从每期正文的核心标题生成 110 至 160 字的唯一 description。
- 从正文提取第一张有效图片，写入 `images` Front Matter。
- 发布网页时移除正文开头重复的一级标题，原始归档内容不丢失。
- YAML 字符串统一安全转义，避免标题或摘要中的引号破坏构建。
- 日期页改用精简栏目导航，不再输出完整历史树。
- Article Schema 读取当期图片，并补 BreadcrumbList。
- 保留月份目录、pager、搜索和 sitemap，历史页面仍可抓取。

验收：最近三类日期页均只有一个 H1；description 随当天内容变化；有图正文能输出文章图；单页链接数量明显下降。

### 阶段 B：雷达接入日报候选池

状态：已完成本地实现、单元测试、线上公开 JSON 只读联调和 Worker dry-run，待远端鉴权恢复

- 新增只读 `LongevityRadarDataSource`，默认读取 `data/briefing-lite.json`。
- 每次最多读取少量高相关条目，默认 8 条，可通过环境变量调低。
- 保留 canonical URL、来源类型、研究对象、发表阶段、风险标记和相关性分数。
- 雷达条目进入现有 URL/标题去重，不另起重复抓取。
- 网络错误、结构错误和单条坏数据均失败隔离。
- 不把雷达相关性分数解释为临床有效性。

验收：数据源测试覆盖成功转换、数量上限、非 HTTP URL 拒绝和请求失败回退；现有全部测试继续通过。

### 阶段 C：内容职责和语义内链

状态：已完成本地实现、完整测试、生产构建和浏览器预览验收，待远端部署门禁解除

- 普通日报回答：发生了什么、证据到哪一步、不能得出什么结论。
- 商机日报回答：谁会付费、今天最小动作、成功指标、停止条件和医疗风险。
- 资讯商机项目回答：项目是什么、怎样试跑、可沉淀什么资产、维护成本和二次开发方向。
- 每篇日期页自动链接所属栏目、雷达、同主题历史内容及另一种行动型栏目。
- 时间线只收录具有可验证日期和一手来源的重要事件，不复制每日正文。

本次实现补充：

- 普通日报提示词改为证据优先，逐条说明来源类型、证据阶段、可信度、应用距离和不能得出的结论，并移除泛 AI 猎奇语气。
- 商机日报新增成功指标和停止条件；项目商机新增许可证、数据可得性、维护成本、24 小时试跑指标和停止条件。
- 三类生成内容均明确不输出一级标题，由网页模板统一提供页面 H1。
- 日期页新增“雷达信号 -> 证据解释 -> 商机验证 -> 项目试跑”行动链，并按六类长期主题连接日期更早的历史内容。
- 旧普通日报缺少 `date` 时，从 `YYYY-MM-DD.md` 文件名读取日期；找不到同主题旧文时仅展示真实的相邻期次，不伪称同主题。
- 行动链同时提供中英文文案，并排除空日期、跨语言和未来日期内容。

验收：同一事实在四个产品中承担不同职责，不出现四份相似摘要。

### 阶段 D：专题中心与长期排名资产

状态：后续内容建设

先建设 6 个专题中心：

1. AI 药物发现
2. AI 蛋白质与多组学
3. 生物年龄与衰老时钟
4. 神经退行性疾病 AI
5. 长寿临床试验与监管
6. AI 长寿开源项目与数据集

每个专题中心包含定义、关键实体、最新进展、代表论文、临床试验、项目、商机、风险边界和最近更新，不做简单标签列表。

验收：日报条目能进入稳定专题；专题页每周更新；Search Console 开始出现非日期型长尾词。

## 5. 内容与医学边界

- 预印本、动物、细胞、观察性研究不得写成人体疗效。
- 雷达分数表示主题相关性，不表示治疗有效、可诊断或可商业化。
- 商机不得承诺逆龄、治疗、诊断、药效或个体结果。
- 所有关键结论优先链接论文、注册库、监管机构或项目仓库。
- 图片必须来自输入材料或允许展示的来源，并保留来源说明；没有合适图片时不伪造。
- 素材不足时允许少发，不用无关通用 AI 或泛健康内容凑数。

## 6. 成本控制

- 不增加 Cron；雷达继续每小时独立更新，日报仍按现有每日任务运行。
- 日报读取雷达轻量 JSON，不重复调用其上游 API。
- 普通日报、商机和项目商机继续共享一次抓取快照。
- 元数据提取、H1 清理和图片识别全部使用确定性代码，不增加模型调用。
- 雷达条目有默认数量上限，避免增加提示词长度。

## 7. 测试与发布门禁

- 后端：运行全部 Node 测试，并新增元数据与雷达源测试。
- 前端：运行 Hugo production 构建，检查 HTML 中 H1、description、JSON-LD、图片和链接数量。
- 雷达：运行 Python、Node 和语法测试，不改变 `bio-radar-v1` 兼容性。
- 只做本地分支修改，不自动部署、不改线上内容。
- 部署前需再次核对 diff、远端最新提交、Worker secrets 和 Pages 预览。
