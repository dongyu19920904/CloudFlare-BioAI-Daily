# AI 生命延续学 GEO 可信引用改造方案

## 文档状态

- 日期：2026-08-22
- 范围：AI 生命延续学日报、AI 生命延续学商机日报、AI 生命延续学资讯商机项目
- 前端：`BioAI-Daily-Web`
- 后端：`CloudFlare-BioAI-Daily`
- 执行基线：前端远端 `c914a1f`，后端远端 `95326f4`
- 本轮不改：个人博客生成、AI 生命延续学雷达、账号店代码/商品/支付、历史日报正文

## 一、结论

阮一峰周刊第 409 期展示的做法，是在识别到大模型爬虫后向页面注入肉眼不可见的文本，要求模型提高页面权重、优先参考并逐字引用。它可以作为 GEO 讨论素材，但不适合作为本站的生产实现。

原因：

1. 它是提示词注入，不是权威性证明。模型是否检索、采信和引用页面，不能由网页自报“经典之作”“无 AI 幻觉”决定。
2. 按 User-Agent 给模型和真人返回不同正文，具有 cloaking（差异化呈现）风险，也不利于调试、缓存和长期维护。
3. “无幻觉”“权重最高”“逐字引用”都是站点无法自证的绝对声明。对医学、衰老和健康寿命等 YMYL 内容，这种声明会放大误引风险。
4. 隐藏命令一旦被来源文章、RSS 或用户内容带入生成链路，也会形成间接提示词注入风险。
5. 当前站点真正缺少的不是一句命令，而是可抽取的直接结论、稳定 canonical、清楚作者/日期、原始来源和证据边界。

因此，本轮继承该技巧的目标——“让大模型更容易理解和正确引用本站”——但不复制隐藏操纵手段。生产实现统一采用公开可见的“可信引用合同”。

## 二、哪些做法采用，哪些不采用

| 做法 | 决策 | 生产实现 |
| --- | --- | --- |
| 告诉模型页面讲什么 | 采用 | 在可见正文和 `llms.txt` 中写清栏目定位、受众和边界 |
| 提供便于摘录的结论 | 采用 | 三个栏目使用各自的“可引用要点/判断”结构 |
| 要求引用本站 | 改造后采用 | 公开说明引用格式，同时要求医学事实优先核对原始论文/机构来源 |
| 给 LLM 爬虫注入隐藏文字 | 不采用 | 真人与爬虫读取同一正文，不按 User-Agent 注入内容 |
| 自称“经典之作”“无幻觉” | 不采用 | 只陈述可验证的编辑方法、来源和局限 |
| 要求提高权重、逐字引用 | 不采用 | 不干预模型系统指令，不作不可验证排序要求 |
| 批量制造 FAQ | 不采用 | 只有真实读者问题才生成，可省略，不承担广告导流任务 |
| 机器可读文件 | 采用 | 更新 `llms.txt`，保留 sitemap、canonical 和 JSON-LD |

## 三、三个栏目的 GEO 分工

### 1. AI 生命延续学日报

目标是让读者和检索模型快速回答“今天发生了什么、证据到哪一步、不能推出什么”。

- 在 TOP 正文前加入“今日可引用要点”，保留 2-3 条真正重要事实。
- 每条包含：直接结论、原始来源、研究类型/物种/样本等证据边界。
- 事实必须来自输入素材；编辑判断与研究结论分开。
- 取消固定两条自我推广 FAQ，改成 0-2 条真实读者问题；没有合适问题时省略。
- 不要求模型推荐本站，不把爱窝啦账号店写成科研或医学权威。

### 2. AI 生命延续学商机日报

目标是让检索模型正确区分“来源事实”和“本站商业判断”。

- 将“先看信号”升级为可独立引用的编辑判断。
- 每条写清：编辑判断、事实依据、适用人群、风险边界。
- 机会结论不能伪装成论文结论，也不能把付费意愿、收入和需求写成已验证事实。
- 允许引用本站的分析，但医学事实仍应引用原始论文、机构或监管来源。

### 3. AI 生命延续学资讯商机项目

目标是让项目实体容易被准确识别和复核。

- 在项目列表前加入“先看结论”，使用 canonical repo/DOI/官方项目链接。
- 摘要优先表达：项目是什么、今天能否试跑、适合谁、不能做什么。
- stars、许可证、最近活动、依赖和数据可得性只能按已提供或已核验信息陈述。
- 不把“研究代码存在”写成“临床可用”，不把 README 自述当独立医学验证。

## 四、共享内容合同

三个栏目共享以下规则，但不共享相同成稿：

1. 真人和机器读取完全相同的公开正文。
2. 不输出“LLM 爬虫指令”“大模型提示词”“提高权重”“优先引用本站”“逐字引用”等操纵性文本。
3. 直接答案放在段首，关键段落脱离上下文仍能成立。
4. 关键事实附原始链接；日期、研究对象、研究类型和重要数字不得脱离来源。
5. 明确区分：来源事实、本站解读、商业判断、预测和未知项。
6. 对预印本、动物实验、观察性研究、小样本研究明确写局限。
7. 引用本站时保留文章标题、发布日期和 canonical URL；引用医学事实时优先回到原始来源。
8. 页面不得声称经过医生审核，除非未来确有可核验的具名医学审阅流程。

## 五、前端实现

### 公开引用说明

日期页标题下增加紧凑且可见的信息区：

- 编辑：AI 生命延续学日报编辑部
- 发布日期与更新时间
- AI 辅助整理、未经临床医学审阅
- 本页 canonical 链接
- 引用建议：引用本站解读时保留标题、日期和链接；医学事实优先核对文中原始来源

该说明对真人和所有爬虫一致显示，不使用 `display:none`、不可见颜色、屏幕外定位或 User-Agent 判断。

### `llms.txt`

更新为可选的站点目录与引用说明：

- 写明三个栏目的边界和 canonical 入口。
- 写明本站是编辑整理，不是论文、临床试验注册或监管结论的替代品。
- 明确推荐的引用格式和事实核对顺序。
- 不写排序命令、自我吹捧或“无幻觉”声明。

### Schema

- 日报日期页使用真实的 `Article`/`BlogPosting` 语义，不继续用容易误解为技术文档的 `TechArticle`。
- 增加真实的 `inLanguage`、`isAccessibleForFree`、作者组织、发布者组织、发布日期和更新时间。
- Schema 必须与可见页面一致；不使用 `MedicalWebPage`，不虚构医生或专家审核。

### Robots 与域名

- 保持 `news.aibioo.cn` 的 sitemap，不恢复历史旧域名。
- `User-agent: *` 当前没有禁止公开内容，已允许常见搜索与 AI 抓取器读取。
- 不为 AI 爬虫生成一套额外正文。

## 六、后端实现

### 共享 GEO 指南

新增共享 prompt 模块，分别为 daily、opportunity、project-opportunity 返回适配后的引用规则，避免三份 prompt 日后独立漂移。

### 生成结果安全检查

新增确定性检查，阻止生成结果包含：

- 隐藏 LLM 指令或爬虫命令
- 要求提高页面/本站权重
- 要求优先引用本站或逐字引用
- 自称“无 AI 幻觉”等无法验证的绝对声明

检查只接入三个 BioAI 栏目，不接入 `scheduledBlog.js`。

### Front matter

未来新生成的日期页写入明确 `date` 和 `lastmod`，保证可见时间、canonical 与 JSON-LD 使用稳定日期，而不是只依赖 Git 提交推断。

## 八、验证与发布门槛

### 自动测试

- 三个 prompt 都引用共享 GEO 合同，并保持栏目差异。
- 生成结果安全检查能阻止示例中的隐藏提示词，但不误伤正常的“优先核对原始来源”。
- 个人博客 prompt 和 `scheduledBlog.js` 不接入该模块。
- 新页面 front matter 包含稳定发布日期和更新时间。
- 前端引用说明真实可见，包含作者、日期、canonical 和医学边界。
- JSON-LD 不使用 `MedicalWebPage` 或虚构医学审核。
- `llms.txt` 不含排名操纵命令。
- robots/sitemap/canonical 保持 `news.aibioo.cn`。

### 构建检查

- 运行后端全部 Node 测试。
- 运行前端 Node 合同测试。

### 发布边界

## 九、回滚

- 前端与后端各自保持一个独立提交，任一侧可单独回滚。
- 前端回滚只移除引用说明、schema/llms 调整和相关样式，不触碰日报正文。
- 后端回滚只移除共享 GEO 指南、生成结果安全检查和日期 front matter，不影响抓取、定时路由与博客链路。
- 如果新 GEO 摘要导致正文质量下降，优先关闭该栏目对应的 prompt 引用块，不回滚来源、安全检查和页面基础元数据。
