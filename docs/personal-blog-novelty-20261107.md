# 个人博客十一月选题重复修复

## 检查结果

截至 2026-11-07，11 月 1、2、4、5、6 日的 AI 工具与实践文章反复讲改代码前检查调用关系，3 日主题不同，保留。重复不仅发生在标题，也发生在开头、例子和读者行动。

根因是 `getBlogReaderBrief` 遇到 Codex / Claude Code / Cursor 等词就指定同一个问题；写作内核还反复示范改按钮和检查关联。选材给编程工具固定高分，没有近期文章上下文，出版检查也不检查跨日重复。11 月 2 日 `/why` 的关联查询能力、6 日两种标签的解释没有对应来源支持，是固定问题诱发的内容偏移，不应仅改标题。

## 最小实施顺序

1. 在隔离 worktree 中修正文生成模块。去掉一刀切的编程问题和单一示例，不更改作者资料、模型线路、cron 或 BioAI 三类任务。
2. 读取目标博客同栏目近 7 天的已发布内容；选材避开已使用来源，提示词加入近期标题及短摘要。标题、正文近似和已反复出现的调用关系角度使用本地确定性检查，不新增模型评分调用。
3. 严重重复走现有唯一一次定向 repair；仍重复则只拒绝该博客，不替换成占位稿。轻度文风警告仍不额外调用模型。历史读取异常与博客失败都不进入 BioAI 日报任务。
4. 五篇存量文章分别依据真实来源改稿，纠正无依据的功能和经历。保留日期及 URL，更新修改日期和摘要，参考资料正常放文末；不新增虚构经历或财务资料。
5. 回归测试选题、源链接、近似检测、历史读取和实际博客 dry-run 链路；完整阅读新预览及五篇改稿。执行前端规定的检查和构建，核对部署后的文章标题及正文。

## 验收与回退

当前五篇不再重复同一读者问题，旧地址仍能阅读，原资料与日间夜间样式不变。用同一输入验证近期历史确实改变选材，重复标题、改写后的同角度正文被拦截；不同功能的同一品牌不误判为重复。生产验证只调用个人博客 preview，不重新生产 BioAI 三份日报。

回退仅撤销本次选题、历史和草稿检查改动，或恢复五个准确文章文件；不复原整个仓库，不清空历史，不改密钥和定时任务。记录实际测试、预览和生产回读结果，不用 CI 成功代替文章验收。
